# 題庫管理規劃：任意 PDF 轉成題庫

> 狀態：第 0 步（技術驗證）已完成（只驗證 Chrome）；第 1、2 步已實作並 commit（分支 `question-bank-manager`）；第 3 步已實作（尚未 commit）；第 4 步以後尚未實作。`questions.js`、`questions.json` 先保留。
> 所有待決定事項都已決定，見「決定紀錄」。

## 目標

- 以後只要提供 PDF，就能產生可以練習的題庫，不必改程式
- PDF 的格式不一定和現在相同：用**樣板**描述格式，樣板可以由使用者在介面上標記範例產生、儲存、之後重複使用
- 每份 PDF 是一份獨立的題庫，可以匯入、匯出，也可以把多份題庫**組合**起來練習
- 題庫管理和測驗分成兩個頁面：管理在 `manage.html`，測驗仍然在 `index.html`

## 最高原則：現有的答題紀錄一筆都不能少

任何一個步驟（拆分題庫、改題目 id、改儲存格式、整理資料夾）都不能讓現有的答題紀錄遺失或改變。具體要求見「九、需要注意與檢查的事項」的第 3 項；不符合就不能發布。

## 決定紀錄

| D2 | 內建題庫有錯時怎麼修 | 介面上也能修正，修正存在使用者自己的資料裡，內建題庫檔不變 |

## 一、整體結構

```
┌──────────── manage.html（題庫管理）────────────┐       ┌──── index.html（測驗）────┐
│ 題庫：從 PDF 建立、匯入、匯出、編輯、刪除       │       │ 選題庫或組合               │
│ 樣板：建立、標記、套用測試、匯入匯出           │ ───>  │ 練習、題目總覽、模擬考     │
│ 組合：把多份題庫合在一起練習                   │       │ 作答紀錄                   │
│ 備份：完整備份與還原                           │       │                            │
└────────────────────────────────────────────────┘       └────────────────────────────┘
                 │                                                     │
                 └──────────── 瀏覽器 IndexedDB（同一個網站共用）───────┘
                       題庫、樣板、組合、作答紀錄
```

- **內建題庫**：放在 repo 的 `banks/`，第一次開啟就能用，不能在介面上刪除；在介面上做的修正存在使用者自己的資料裡，內建題庫檔不變（見「H. 修正題目」）
- **使用者的題庫**：存在瀏覽器的 IndexedDB，用檔案匯入、匯出
- 兩個頁面在同一個網站下（同一個資料夾雙擊開啟，或 GitHub Pages），共用同一份 IndexedDB

## 二、資料模型

| 東西 | 內容 | 檔案（匯出時） |
| --- | --- | --- |
| 題庫 | id、類別 key、類別名稱、年份、來源檔名、使用的樣板、題目、人工修正 | `<題庫 id>.quizbank.json` |
| 內建題庫的修正 | 使用者對內建題庫做的修正（D2），依題庫 id 分組 | 包在完整備份裡 |
| 樣板 | 拆題規則 | `<名稱>.template.json` |
| 組合 | 名稱、包含的題庫 id（不複製題目） | 包在完整備份裡 |
| 作答紀錄 | 欄位式格式（見「檔案格式」），作答歷程沿用版本 3 的精簡陣列 | `quiz-record.json` |
| 完整備份 | 以上全部 | `quiz-backup-<時間>.json` |

### 檔案格式（JSON 瘦身）

repo 裡和匯出的 JSON 一律用欄位式格式：

```json
{
  "format": "pdf2quiz-bank",
  "version": 4,
  "bank": { "id": "ETH-2024-7K3Q", "key": "ETH", "name": "職業道德", "year": 2024 },
  "questions": {
    "columns": ["seq", "num", "question", "options", "answer"],
    "rows": [
      [1, 1, "金融從業人員從事保險招攬行為，下列那一項是錯的？", ["…", "…", "…", "…"], 3]
    ]
  },
  "corrections": {
    "columns": ["seq", "field", "from", "to", "note"],
    "rows": [[279, "answer", 1, 4, "PDF 印的是 (1)，第 4 個選項是「以上皆是」"]]
  }
}
```

1. 每個檔案最上層都有 `format` 和 `version`，匯入時依此判斷檔案種類
2. 一筆一筆的資料一律用 `{ columns, rows }`；格子裡可以放陣列（選項、作答歷程）
3. 讀取時依欄位名稱對應，不依位置：舊程式讀新檔時忽略不認得的欄位，新程式讀舊檔時把缺少的欄位補預設值
4. 同一份題庫內相同的值不重複寫：科目寫在 `bank`，題目 id 由題庫 id 加流水號 `seq` 推出；`num` 是 PDF 上印的題號，只用來顯示
5. 只在讀檔、存檔時轉換，程式內部仍用物件（同現在的 `packRecords()`）
6. 雙擊開啟用的 `.js` 檔內容相同，例如 `window.QUIZ_BANK = { … };`

| 檔案 | 格式 |
| --- | --- |
| 題庫（`banks/`、`.quizbank.json`） | 欄位式 |
| 作答紀錄（`quiz-record.json`、IndexedDB） | 欄位式，依題庫分組，題目只寫流水號 |
| 模擬考成績、完整備份 | 欄位式 |
| 樣板 | 一般物件（只有一筆、欄位不固定） |
| `package.json`、`package-lock.json` 等工具設定檔 | 不改（格式由工具規定） |

實測：題庫 443 KB → 273 KB（約 −38%）；作答紀錄 13.2 KB → 11.9 KB（約 −10%，v3 已經很精簡，主要是為了格式一致）。

**匯入相容**：寫入一律用新格式；讀取時依內容判斷——有 `format` 和 `version` 的是新格式；最上層是陣列的是舊題庫 `questions.json`；有 `items` 的是作答紀錄 v1、v2、v3；舊 id（`ETH-0001`）讀入時轉成新 id。全部轉成內部物件後流程相同。

### 題庫 id

格式：`{類別 key}-{西元年}-{4 碼隨機}`

| 部分 | 規則 | 例子 |
| --- | --- | --- |
| 類別 key | 3～6 個字元，大寫英文或數字 | `ETH`、`MKT`、`INSUR` |
| 年 | 西元年；沒設定時用 `0000` | `2024`、`0000` |
| 隨機碼 | 4 碼大寫英文加數字，排除容易看錯的 `0 O 1 I L` | `7K3Q` |

- 建立題庫時產生隨機碼，和現有題庫重複就重新產生
- 類別 key 和顯示名稱分開存：key 是 `ETH`，名稱是「職業道德」
- **一個 key 只對應一個名稱**（D4）：建立題庫時輸入已經存在的 key，自動帶入它的名稱且不能修改；要用不同的名稱就必須換一個 key
- **題庫建立後，id 只能看、不能修改**：要換類別或年份，就另存成新題庫
- 民國年要換算成西元年（民國 + 1911），例如 113 年 = 2024

### 題目 id

`{題庫 id}-{4 位數流水號}`，例如 `ETH-2024-7K3Q-0012`

- **流水號**（`seq`）：題目在這份題庫裡的順序，從 1 開始（D1）。PDF 上印的題號另存為 `num`，只用來顯示，所以題號重複（例如分成 Part I、Part II）也不會撞 id
- 現有兩份題庫的題號本來就從 1 連續到最後，流水號和題號相同，所以 `ETH-0001` 直接對應 `ETH-2024-xxxx-0001`
- **題庫存檔後，流水號就固定**：重新套用樣板時，用「題號 + 題目文字」對應到既有的流水號；新解析出來的題目接在最後面，不重新編號

- 作答紀錄只認題目 id，不管題目是從哪份題庫或組合出的。同一題單獨練習或在組合裡練習，紀錄都是同一份
- 所以作答紀錄**全部存在同一份**，不依題庫分開（取代舊規劃的「紀錄依題庫分開存」）
- 題目 id 一旦產生就不能再改，否則作答紀錄會對不到題目
- 流水號超過 9999 時需要另外處理（目前的題庫最多 616 題，先不處理，但建立題庫時要檢查並提示）

### 組合

- 只記題庫 id，不複製題目
- 在組合裡，**同一個類別 key 算同一個科目**。例如 `ETH-2024-xxxx` 和 `ETH-2025-xxxx` 放進同一個組合時，模擬考把它們當成同一科；一個 key 只有一個名稱，所以科目名稱不會不一致
- 匯出組合時，可以選擇輸出成一份完整的題庫檔（包含題目本身）給沒有原始題庫的人。題目 id 不變，作答紀錄照樣對得上
- 不同題庫裡文字相同的題目會被偵測出來並提示，**兩題都保留**，各自有自己的作答紀錄（D3）
- 模擬考的預設值（各科題數、及格分數、時間）存在組合裡；只選單一題庫時用目前的預設（各科 50 題、70 分及格）

## 三、各個流程

### A. 從 PDF 建立題庫

```
上傳 PDF → 取出文字 → 自動推薦樣板（依符合率排序）
   ├─ 符合率高 → 選用
   └─ 都不合 → 新建樣板：標記 2～3 題範例 → 儲存樣板
→ 預覽與檢查 → 手動修正少數題目 → 填題庫資訊（類別 key、名稱、年份）→ 儲存
```

- 同一份 PDF 出新版時（例如 113 年改 114 年），建立新題庫，不要覆蓋舊的

### B. 建立樣板（標記範例）

使用者在**程式取出的文字**上選取一段，再標上它是什麼：

| 標記 | 例子 |
| --- | --- |
| 題號 | `12` |
| 題幹 | `下列何者正確？` |
| 選項（依序 1、2、3…） | `(1) 股票` `(2) 債券` |
| 答案 | `(3)`、`B` |
| 忽略 | 頁首、頁尾、頁碼 |

- 程式從標記和標記之間的文字推出規則：答案在題號前或選項後、選項標記的樣式、選項數量
- 至少標 2～3 題，程式才分得出固定格式和巧合（題目有沒有折行、選項是不是剛好四個）
- 樣板存成可讀的設定，進階使用者可以直接修改：

```json
{ "name": "答案在題號前・(1)~(4)",
  "start": "(答案) 題號", "optionMarker": "(1)", "options": 4,
  "answer": { "position": "beforeNumber", "format": "digit", "multi": false },
  "ignore": ["答案 題號 題目", "^\\d+$"] }
```

- 內建樣板放在 repo（例如現在這種格式、`1. 題目 (A)…(D)`、`①②③④`）；自己建的樣板存在瀏覽器，可以匯入匯出

### C. 套用樣板與檢查

- 符合率：解析出幾題、幾段無法解析
- 題號檢查：跳號、重複（題號重複時提示，但不影響題目 id，因為 id 用的是流水號）
- 選項數不符合樣板、答案超出選項範圍、題目或選項是空的、題目重複
- 預覽前幾題；無法解析的段落用顏色標出來
- 少數題目失敗時，可以在預覽中直接修正（見「H. 修正題目」）

### D. 匯入、匯出

- 匯出題庫：一份題庫一個 `.quizbank.json`
- 匯入題庫：
  - id 重複時，詢問要取代還是另存為新題庫（另存會產生新的隨機碼）
  - 和內建題庫的 id 重複時一律另存，內建題庫不能被取代
  - 取代時如果題目內容有變動，列出差異
- 完整備份：題庫、樣板、組合、內建題庫的修正、作答紀錄一個檔案；還原時一鍵匯入

### E. 組合

- 勾選幾份題庫，存成一個組合
- 偵測重複題目並提示，兩題都保留（D3）
- 組合裡同一個類別 key 的題庫算同一科

### F. 測驗

```
開啟 index.html → 選題庫或組合（記住上次的選擇）→ 練習、總覽、模擬考（同現在）
```

- 頁面上加「題庫管理」的連結
- 統計、出題條件、題目總覽只算目前選的題庫或組合
- **進度標籤「已作答」／「未作答」**（D5）：
  - 定義：作答過至少一次（`correct + wrong > 0`）是「已作答」，否則是「未作答」
  - 出題條件：「進度」群組同時有「已作答」和「未作答」（目前只有「未作答」），都可以設為不限、包含、排除
  - 題目總覽：每一題都顯示其中一個標籤（目前只有未作答的題目有標籤）
  - 統計列已經有「已作答」題數，不用改
  - 補測試：包含「已作答」的題數等於排除「未作答」的題數；兩者加總等於題庫總題數；總覽裡每題剛好有一個進度標籤

### G. 刪除題庫

- 刪除前提示「這份題庫有 N 筆作答紀錄」，讓使用者選擇保留或一併刪除
- 保留的紀錄不影響任何東西；之後再匯入同一份題庫（id 相同），紀錄自動接回

### H. 修正題目（D2）

- **使用者的題庫**：修正直接記在題庫檔的 `corrections`（哪一題、哪個欄位、原本的值、改成的值、說明），重新套用樣板時自動套上
- **內建題庫**：修正存在使用者自己的資料裡（IndexedDB 與完整備份），依題庫 id 分組，格式和 `corrections` 相同；載入內建題庫時套上，內建題庫檔本身不變
- 內建題庫之後在 repo 更新時：
  - 內建題庫的值已經等於修正後的值 → 這筆修正多餘，自動移除
  - 內建題庫的值既不是修正前、也不是修正後的值 → 提示衝突，先沿用使用者的修正
- 修正只能改題目文字、選項、答案，不能改流水號（題目 id）
- 修正答案時不重新判定過去的作答（D7）：保留當時的對錯與分數，只影響之後的作答

## 四、解析：pdf.js 為主，Python 選用

- 題庫管理頁預設用 pdf.js 從 PDF 取出文字
- **Python 工具只負責取出文字**，不負責拆題。輸出格式和 pdf.js 的結果一致（一行一筆、去掉頁碼），題庫管理頁提供「匯入 Python 取出的文字」
  - 樣板、預覽、檢查、手動修正都只寫一套
  - 使用時機：pdf.js 取出的文字有問題（中文斷行、順序錯亂），而且使用者已經有 Python 和 pdfplumber
  - 網頁不能執行 Python：使用者在終端機執行一行指令，再匯入結果；README 要寫清楚
- 標記樣板用的文字和解析用的文字必須是同一份：不接受使用者從 PDF 閱讀器複製貼上的文字（換行、空白會不一樣）
- 第一版不支援：答案只用顏色或粗體表示、掃描檔（需要 OCR）、雙欄排版、題目含圖片或表格、答案集中在答案表（放在之後的階段）

## 五、本機與線上（GitHub Pages）

兩邊功能相同。不論哪一種，資料都只存在使用者自己的瀏覽器裡：線上版沒有伺服器，匯入的題庫不會傳到 GitHub，別人也看不到。

### 資料可能消失的情況（要明確提醒使用者）

- 清除瀏覽器資料、使用無痕視窗
- 換電腦、換瀏覽器
- **Safari 會自動清除 7 天沒開啟的網站資料**（iPhone、iPad 也是）
- 磁碟空間不足時，瀏覽器可能自動清除

### 配套

以下是提醒使用者資料生命週期的機制，不保證資料在瀏覽器重開後還在（見下方「範圍」）。在會清除網站資料的環境裡，依賴瀏覽器內記錄的提醒（例如「上次備份 N 天前」）也會跟著重置，這是可以接受的。

1. 完整備份一鍵完成：**題庫和作答紀錄一定要一起匯出**，只有其中一個沒辦法使用
2. 提醒時機：
   - 第一次匯入題庫時說明一次
   - 頁面固定顯示「上次備份：N 天前」
   - 超過 7 天沒備份，或備份後新增很多作答時才提醒，不要每次都跳
3. 呼叫 `navigator.storage.persist()` 請瀏覽器不要自動清除
4. Chrome / Edge：現有的「連結紀錄檔」（只有作答紀錄）維持不變；另外新增「連結備份檔」（題庫、樣板、組合、作答紀錄都自動寫入），兩者並存
5. README 說明：內建題庫要 commit 到 repo 才會出現在線上版；自己匯入的題庫只有自己的瀏覽器看得到

### 範圍：不處理瀏覽器重開後的資料保存

只要求**頁面開著、資料沒被清除的期間**一切正常。瀏覽器重開、重開機之後資料是否還在，不在本規劃的處理範圍內（使用者的公司電腦關閉 Chrome 就會清除網站資料，已接受）。需要保留時，由使用者自己匯出備份或連結紀錄檔；上面的「配套」維持原樣，作為提醒，不另外加強。

## 九、需要注意與檢查的事項

### 1. 實作前的技術驗證（第 0 步）

**Chrome 已驗證（2026-10-30，Chrome 155，pdfjs-dist 3.11.174）**，其他瀏覽器不驗證（見下方）。

| 項目 | 結果 |
| --- | --- |
| `file://` 下不同 html 檔共用 IndexedDB | ✅ 同資料夾、子資料夾都共用（origin 一律是 `file://`） |
| pdf.js UMD 版在 `file://` 讀 PDF | ✅ 用檔案選擇讀入；主執行緒和 Worker 兩種模式都可以 |
| 速度 | ✅ 49 頁約 0.12 秒、29 頁約 0.11 秒 |
| pdf.js 與 pdfplumber 的文字差異 | ✅ 行數完全相同（1925、1126 行），只有空白不同 |
| 用 pdf.js 文字套現有拆題規則 | ✅ 1120 題全部拆出；1119 題和現有題庫一致（忽略空白），唯一不同的是 ETH-0279（人工修正，見第 2 項） |
| `navigator.storage.persist()` | ⚠️ 支援，但回傳 `false`（沒有同意） |
| 重新啟動 Chrome 後資料是否還在 | 不在範圍內（見「五、範圍：不處理瀏覽器重開後的資料保存」） |
| 關掉分頁（瀏覽器還開著）後重新開啟、重新整理 | ✅ 用現有的 `index.html` 實測：作答後 20 毫秒以上才關閉或重新整理，5 次都保留；只有在作答的同一瞬間（0 毫秒）關閉才會遺失最後一筆（IndexedDB 是非同步寫入）。人操作不可能這麼快，可視為正常 |

**驗證時發現、實作時要處理的事**：

- 取出文字時，每頁的文字項目依 y 座標分行、依 x 排序；同一行兩個項目的間距超過字高 0.3 倍時補一個空白，但兩個中文字之間不補
- PDF 本身在中文字之間帶有空白（例如 `在 貨 幣 市 場 上`），取完每一行後，要去掉兩個中日韓文字或全形標點之間的空白
- pdf.js 在中文和數字之間一律有空白（`停止招攬 1 年`），pdfplumber 則有時有、有時沒有。用 pdf.js 重新產生現有題庫的話有 46 題只差空白；因此內建題庫直接從現有 `questions.json` 轉換，不受影響（見「六、現有題庫的轉換」），這個差異只出現在之後用 pdf.js 新建的題庫
- `file://` 下所有本機 html 檔共用同一個儲存空間：電腦上任何雙擊開啟的網頁都讀得到這裡的資料
- `persist()` 不被同意時，只能靠備份提醒和連結備份檔來保護資料
- 可選的保險：在 `pagehide` 時，若還有寫入沒完成，同步寫一份到 localStorage。現有的 `loadRecords()` 下次載入時本來就會合併 localStorage 的資料，所以不需要其他改動

**其他瀏覽器**：不做驗證（2026-10-30 決定）。以 Chrome 的結果為準；其他瀏覽器若有功能不支援（例如沒有檔案寫入功能），程式偵測到後停用該功能並彈窗提示「這個功能在目前的瀏覽器無法使用」，不修改、也不要求使用者修改瀏覽器設定。
