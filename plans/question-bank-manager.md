# 題庫管理：尚未完成的項目

> 主要需求（任意 PDF 轉成題庫、題庫管理頁、樣板、組合、完整備份、修正題目、現有紀錄的轉換）已經完成，做法見 README 與 CLAUDE.md。這份文件只列還沒做的延伸與優化。
>
> 不論做哪一項，最高原則不變：**現有的答題紀錄一筆都不能少**，作答歷程與標記要完整保留、重算結果不變；只改網頁程式，不修改、也不要求使用者修改瀏覽器的設定。

## 一、資料安全與備份

- [ ] **連結紀錄檔的原檔備份**：開啟舊格式（版本 1～3、舊 id）的紀錄檔時，第一次寫回新格式之前先備份原檔。目前只有瀏覽器裡的紀錄會先存一份 `records-backup-before-v4`，連結的檔案會直接被改寫成新格式
- [ ] **連結備份檔**（只有 Chrome / Edge）：除了現有的「連結紀錄檔」（只有作答紀錄），另外可以連結一個完整備份檔，題庫、樣板、組合、作答紀錄都自動寫入；兩者並存
- [ ] **備份提醒**：目前只看「超過 7 天沒備份」。規劃中的「備份後又新增很多作答」也要提醒，但不要每次都跳

## 二、題庫管理

- [ ] **重新套用樣板到既有題庫**：例如樣板改好之後重新拆同一份 PDF。題庫存檔後流水號就固定，要用「題號 + 題目文字」對應既有的流水號，新題目接在最後；使用者題庫的 `corrections` 要自動套上、不能被蓋掉，衝突時提示
- [ ] **取代題庫時列出差異**：目前只顯示「N 題不同」，要列出是哪幾題、哪個欄位不同
- [ ] **匯出組合（含題目）**：在沒有原始題庫的瀏覽器也能直接使用，題目 id 不變
- [ ] **大量題庫的效能**：數十份題庫、上萬題時的載入速度與 IndexedDB 空間，目前沒有測過

## 三、解析格式的延伸（之後再做，等拿到實際的 PDF 當測試資料）

- [ ] **答案表格式**：答案集中在最後或每章最後（`1.C 2.A …` 或表格）。拆題時答案先空著，再找出答案表依題號對回去；要處理每章題號重新從 1 開始、表格在取出的文字裡順序錯亂
- [ ] **雙欄排版**：pdf.js 會把左右兩欄同一高度的文字接成一行。要在取文字時依 x 座標分欄（先左欄、再右欄），並偵測哪幾頁是雙欄、處理跨欄標題
- [ ] **多選題**：題目格式目前只有單選；答案改成可以有多個、計分規則另外設計
- [ ] **掃描檔（OCR）**：建議不放進網頁（Tesseract.js 加繁中語言檔要多十幾 MB，雙擊開啟時大概不能用，中文準確率也普通）。改成 `tools/extract_text.py` 加 `--ocr` 選項，用使用者電腦上已經有的 OCR（Tesseract、PaddleOCR），輸出一樣用「匯入 Python 取出的文字」。取不到文字時的提示也要說明可以這樣做
- [ ] **只用顏色或粗體標示答案**：OCR 和目前的取文字都會丟掉顏色與字型，要從 PDF 讀字型和顏色資訊
- [ ] **需要 CMap 的中文 PDF**：雙擊開啟時沒辦法載入 pdf.js 的 cmaps，這類 PDF 會取不到文字（目前和掃描檔顯示相同的提示）

## 四、驗證與清理

- [ ] **其他瀏覽器**：目前只在 Chrome 驗證過；Edge、Firefox、Safari（含 iPhone / iPad）都還沒測，尤其是 IndexedDB、pdf.js、跨分頁通知
- [ ] **檢查是否還有其他手動修正過的題目**：用 git 紀錄和 PDF 重新解析的結果比對內建題庫（目前已知只有 ETH 第 279 題）
- [ ] **拿掉舊檔案**：`questions.js`、`questions.json`、`parse_pdf.py` 目前先保留，確定不需要後再刪除（README 的檔案表要跟著改）

## 五、計分：時間衰減（待決定）

分數的目的是預測「下次考試遇到這題還會不會錯」：分數越高，代表越不會錯。目前的分數只看作答歷程，不看隔了多久，所以「今天連對 3 次」和「三個月前連對 3 次、之後沒碰」都是 8 分，高分端都擠在上限、看不出差別。

**建議做法（尚未決定，參數都是暫定）**

- [ ] 上限維持 8：分數本質上像「不會錯的機率」，有上限是合理的；提高上限只會讓數字變大，預測不會變準
- [ ] 分數隨時間衰減：距離上次作答越久，目前的分數越低（只對正分衰減）
- [ ] 衰減速度看熟練程度（間隔重複的概念）：只答對一次的題目約 3 天降一半；每多連對一次，降一半所需的時間加倍（6、12、24 天…），最長約 60 天
- [ ] 只影響顯示、篩選、排序與出題：作答紀錄和存檔格式都不變，每次載入時依「現在的時間」重算目前的分數
- [ ] 參數放在 `js/config.js`（最短、最長的半衰期、每次連對的倍數），README 的「計分規則」與頁面上的「分數怎麼算？」要同步更新

**決定前要先想清楚的影響**

- 分數每天都會變：一段時間沒練的題目會慢慢掉出「已記住」，回到出題範圍（這正是複習要的效果，但已記住的題數會變少）
- 「分數低到高」排序與弱點加權的隨機出題，會自然優先出很久沒練的題目
- 分數區間的篩選、統計的「已記住」、題目總覽顯示的分數都會跟著時間變動
- 和既有規則的關係：速度加權（答得快加分多）、10 分鐘內重複答對不加分都維持，和衰減不衝突
- 測試需要用可控時鐘（`page.advance`）驗證隔幾天後的分數
